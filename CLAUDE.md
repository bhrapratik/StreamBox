## Project overview

StreamBox is a multi-module Android project built with Gradle Kotlin DSL (Kotlin 2.2.10, AGP 9.2.1). It currently consists of scaffolding generated by Android Studio templates — no app-specific business logic, networking, or data layer has been implemented yet. Three modules:

- `:core` — Android **library** module (`com.streambox.core`). Intended to hold shared logic between `mobile` and `tv`. Currently empty aside from template test stubs.
- `:mobile` — Android **application** for phones/tablets (`com.streambox.mobile`), uses Jetpack Compose + Material 3.
- `:tv` — Android **application** for Android TV (`com.streambox.tv`), uses Jetpack Compose with `androidx.tv:tv-material` (not Material 3) and the Leanback launcher category.

Both `mobile` and `tv` depend on `:core`. All modules target `minSdk 26`, `compileSdk 36`, Java 11.

## Common commands

Build and test via the Gradle wrapper from the repo root (`./gradlew`, not a global `gradle`):

```bash
./gradlew build                      # build all modules
./gradlew :mobile:assembleDebug      # build the phone app APK
./gradlew :tv:assembleDebug          # build the TV app APK
./gradlew :core:assembleDebug        # build the core library AAR

./gradlew test                       # run all JVM unit tests
./gradlew :mobile:testDebugUnitTest  # unit tests for one module
./gradlew :mobile:testDebugUnitTest --tests "com.streambox.mobile.ExampleUnitTest"  # single test class
./gradlew :mobile:testDebugUnitTest --tests "com.streambox.mobile.ExampleUnitTest.addition_isCorrect"  # single test method

./gradlew connectedAndroidTest                      # instrumented tests on a connected device/emulator
./gradlew :tv:connectedDebugAndroidTest              # instrumented tests for one module

./gradlew lint                       # Android Lint across all modules
./gradlew :mobile:lintDebug          # lint one module/variant
```

Gradle configuration cache is enabled (`org.gradle.configuration-cache=true` in `gradle.properties`); if a build misbehaves after structural changes (e.g. editing `build.gradle.kts`), rerun with `--no-configuration-cache` to rule out a stale cache before debugging further.

## Architecture notes

- Dependency versions are centralized in `gradle/libs.versions.toml` (the Gradle version catalog) and referenced via `libs.*` in each module's `build.gradle.kts`. Add/bump dependencies there, not as inline coordinates in a module build file.
- `mobile` and `tv` each define their own `ui/theme/{Color,Theme,Type}.kt` (both themed as `StreamBoxTheme`) — these are currently independent/duplicated template themes, not shared via `:core`.
- `tv` deliberately uses `androidx.tv:tv-material` components instead of `androidx.compose.material3` for TV-appropriate focus/d-pad navigation behavior; don't introduce plain Material 3 widgets into TV screens.
- `release` build types in `mobile` and `tv` currently have code optimization explicitly disabled (`optimization { enable = false }` in each `build.gradle.kts`).
- This directory is not yet a git repository.
